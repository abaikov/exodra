"Rows are matched by key, and the key rules are ours"

Both panels render the same rows from the same data, each through a reconciler made once with createExoChildrenReconciler and called from an effect. The left one is made with the row machine alone and reconciles by object identity. The right one is made with { key: item => item.id } and matches rows by item.id.
Press Refetch: the data comes back as freshly parsed objects, the way a poll returns it. Nothing on the left is the same object any more, so every row is rebuilt. Every row on the right is matched by its key and kept — the build stamps stand still. When a kept key arrives under a new object, the row's wire runs again with that object.
Nothing is composed onto the backend for either panel: the reconciler is a function from @exodra/list-reconcile that drives the children port every DOM backend has, and it remembers what it showed, so neither machine keeps a list of its own.

Core — reconciled by identity

createExoChildrenReconciler(ROW)(c, P.rows, want)

Option — reconciled by key

createExoChildrenReconciler(ROW, { key: item => item.id })(c, P.rows, want)
