A context travels down a render, and stops at its edge

All three panels put the same widget component in the same place in the document — inside a <div class="host-slot"> that a host drew — and the host's createInitialState calls c.provide(THEME, source) in every one of them. The widget calls c.inject(THEME) and never mentions the host. What differs between the panels is only who mounted the widget, and that is what decides the answer.
Panel 1 mounts it inside the host's render, with c.one: the chain the host extended is threaded down to it and it comes up in the host's theme.
Panel 2 mounts it with a second, independent backend.render into the empty div the host drew. It lands in the identical DOM position and reads undefined. A render inherits nothing from the document around it. Nothing walks up from where a mount landed, no element carries a mark, and there is no observer that would notice one appearing later — so this is not a race and no ordering fixes it.
Panel 3 is the answer to panel 2: the value is passed. The page's own script owns the source, so it mounts a one-element root of its own whose createInitialState does c.provide(THEME, source) and then c.ones the very same widget. Two independent mounts again, the same position again, and the theme arrives — as data, through a call, never through the tree.
